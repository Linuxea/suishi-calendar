# 中国风格个人 Web 日历 · 市场调研报告

**日期**：2026-09-06
**调研目的**：为「岁时」——个人使用的中国风格 Web 日历——立项提供依据：摸清国内日历类产品格局、确认"中国风格日历的基本功能"基准、评估技术实现成本。

## 一、市场格局：四类玩家

### 1. 手机系统日历 —— 用户基数最大，但锁死在手机端

- **华为日历**：地区设为中国后支持农历显示、重要日管理、锁屏农历（限预置主题），并提供"订阅管理"扩展服务（星座、课程表等）。
- **小米日历**：内置星座/赛事/追剧/节日订阅与日程提醒；黄历宜忌一般要靠第三方 App（日历通、万年历等）补充。

农历+节气已是国产系统日历标配，但没有 Web 端，订阅内容也日益运营化、广告化。

### 2. 万年历类 App —— "中国风"功能最全，体验最差

- **中华万年历**（优路科技，51wnl.com）：农历公历对照、假日节气、黄历宜忌、吉日查询，外加天气、记事、资讯流、云同步，号称全球用户量领先。注意「51万年历」与「中华万年历」同属一家公司，功能高度重叠。
- **万年历**（OrangeStudio）：每日宜忌、星座属相、放假调休、老黄历冲煞。
- **黄历-中华万年历**（iOS）：宜忌、节气倒计时、法定假期农历对照、择吉八字简盘，主打"**全部本地计算，无需联网**"——该卖点本身验证了用户对隐私与离线的诉求。
- **农历黄历中国日历**（Microsoft Store）：离线、无广告。
- **中华农历节气日历万年历2**：200 年黄历数据。

痛点一致：广告与资讯流泛滥、功能臃肿，**Web 版基本只是 SEO 引流页，体验割裂**。

### 3. 效率日程类 —— 日程管理最强，中国历法只是皮

- **滴答清单**（TickTick 国际版）：全球超千万用户的国内头部"待办+日历+番茄钟+习惯打卡"工具，跨平台与云同步成熟，但核心功能付费订阅。
- **Google / Apple Calendar**：纯国际风，农历仅一行小字，没有节气、调休、黄历概念，农历生日提醒这类需求支持很弱。

### 4. 开源/在线小工具 —— 最接近本项目形态，证明需求真实

- **ChinaCalendar**（yangh9）：在线 Web 日历——节日纪念日、法定节假日调休补班、二十四节气、干支农历。
- **合社日历 He-Calendar**（uTools 插件）：定位"有温度的中国风日历/数字艺术品"——证明中国风审美本身就是卖点。
- **吉易 Chinese Almanac**：基于 lunar-javascript 的纯客户端黄历/八字择日，验证纯前端可行。
- **infinet/lunar-calendar**：iCal 订阅格式的农历/节气/传统节日。

## 三、开源技术生态：历法成本接近零

- **lunar-typescript**（6tail，lunar-javascript 的 TS 版）：零第三方依赖，覆盖公历/农历/佛历道历、星座、儒略日、干支、生肖、节气、节日、彭祖百忌、**每日宜忌**、吉神凶煞——宜忌不需要自己造数据。官方新推升级版 **Tyme/tyme4ts**（架构更现代，支持藏历回历/月相），但老黄历类功能 lunar 系更全，本项目选 lunar-typescript。
- **holiday-cn**（NateScarlet）：每日自动抓取国务院公告的中国法定节假日 JSON，CI 自动更新，可经 jsDelivr 直接读取——调休数据不用自己维护，每年年底自动跟进次年安排。
- **chinese-days**（vsme）：节假日+调休+节气查询函数与 JSON，可作备选。
- **traditional-chinese-calendar-database**：1901–2100 年公农历对照 JSON 数据库，备用。

**结论：历法计算全部有现成库，自研工作量集中在日历 UI、日程管理与本地存储。**

## 四、差异化机会

1. **Web 端空白**：万年历功能锁在 App 里且广告缠身，Web 上没有体验好的中国风日历；效率日历 Web 强但无中国历法深度。"万年历有历法没体验，效率日历有日程没中国味"——两端割裂就是位置。
2. **本地优先、数据自主**：纯前端+本地存储+可导出，无账号无追踪无广告；"全部本地计算"在 App 市场已被验证为有效卖点。
3. **农历生日/纪念日**：高频刚需且是竞品弱项，按农历每年重复的事件是差异化功能。
4. **中国风审美**：合社日历证明"数字艺术品"定位有受众；国际风产品主导 Web 端，审美差异化空间明显。
5. **私有部署**：静态构建可挂到自有服务器（如自有服务器 `/calendar/` 子路径），私人可达。

## 五、风险与注意

- **调休数据时效**：国务院每年年底（11 月前后）公布次年安排，holiday-cn 会自动跟进，但需要数据更新机制（运行时拉 CDN + 本地缓存 + 内置当年快照兜底）。
- **宜忌属民俗文化参考**：明确呈现为"传统文化参考"并提供总开关（已确认做成可开关），不做"准确性"承诺。
- **远年份边界**：农历换算库在 2100 年前后有边界，个人使用无影响。
- **Web 提醒受限**：浏览器 Notification 在移动端 Web 受限，提醒功能以桌面浏览器为主。

## 六、结论

市场已验证"中国历法+日程管理"的组合需求，但供给两端割裂；开源库把历法成本降到近零；个人自用场景天然免去账号、合规、多端同步的包袱。做一款**农历为第一公民、日程管理完整、无广告、本地优先、中国风视觉**的个人 Web 日历，定位清晰、成本可控、差异化明确。
